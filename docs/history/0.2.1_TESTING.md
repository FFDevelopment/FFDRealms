## Native checks included

Run **Run Tests.bat**, choose your existing Godot executable, and inspect `test-results.log`. The runner stops on an error exit or reported engine/script/parse error. It runs headless import, the original simulation suite, the Northreach suite, the new appearance/safety suite, and the main-scene smoke suite.

```text
godot --editor --headless --audio-driver Dummy --path . --quit
godot --headless --audio-driver Dummy --path . --script res://tests/test_runner.gd
godot --headless --audio-driver Dummy --path . --script res://tests/frontier_runner.gd
godot --headless --audio-driver Dummy --path . --script res://tests/appearance_runner.gd
godot --headless --audio-driver Dummy --path . --script res://tests/smoke_runner.gd
```

Use the actual path/name of your Godot executable. Tests do not read or modify the three real profile slots. New file round-trips use only `user://test_profiles/appearance_roundtrip.json`; automated simulation instances have autosaving disabled. Normal game appearance saves update only the selected profile.

`appearance_runner.gd` covers default isolation, invalid inputs, every dye channel, cosmetic-only commits, town-only customization, independent NPC/player materials, fabric/detail swaps, cached textures, rotatable draft preview, reset/discard semantics, JSON persistence, legacy defaults, inclusive boundaries, enemy-only paths, around-camp return, stale movement routes, invalid spawn/state repair, and safe-entry-during-windup handling.

`smoke_runner.gd` additionally opens the real HUD wardrobe, edits without committing, discards, saves a new look in test mode, checks the real actor material/detail change, and retains the original fishing, lighting, world-target and moving-enemy smoke checks.

## Limits

Still single-player. Cosmetic garments are not lootable clothing/armor inventory items and do not grant stats. Textures and meshes are lightweight procedural prototypes, not final character art. Body exclusion uses a conservative margin for current creatures; future larger models or newly added towns require corresponding layout changes and tests. No native/runtime or performance guarantee is claimed by the offline reports. Roll back using a pre-update save backup: 0.2.0 drops the new appearance field when re-saving.

## Native checks included for your PC

Run **Run Tests.bat**, supplying your existing Godot executable when asked. It writes `test-results.log` in the project directory and stops on an error exit or reported script/parse error.

The stages are:

1. Headless editor import.
2. `tests/test_runner.gd`: existing inventory, gathering, one-click combat, bait, all-bank fishing, crafting, economy, quest and isolated-save checks. Dynamic enemy position assertions and the new windup timing replace old fixed-spawn assumptions.
3. `tests/frontier_runner.gd`: new-region navigation, pursuit, live-target hits, click spam rejection, timing, dodge/cover, leash/return protection, enemy death, species loot and respawn, expedition rewards, steel gates, shared storage, legacy save fields and map-coordinate round trips.
4. `tests/smoke_runner.gd`: main-scene/HUD construction, all 36 target visuals, original fishing controls and lower lighting, new Ranger UI, moving enemy roots, warning-ring state and dead-enemy click-layer removal.

These suites do not read, replace or delete the three real player profile slots. The legacy save suite creates isolated files under `user://test_profiles`; the new frontier suite does not write saves.

Direct commands, from the project folder, for users running Godot from a terminal:

```text
godot --editor --headless --audio-driver Dummy --path . --quit
godot --headless --audio-driver Dummy --path . --script res://tests/test_runner.gd
godot --headless --audio-driver Dummy --path . --script res://tests/frontier_runner.gd
godot --headless --audio-driver Dummy --path . --script res://tests/smoke_runner.gd
```

Use your actual executable name/path instead of `godot` as needed. A headless pass still requires manual visual/controls testing.

## Known prototype limits

This is still single-player and uses procedural blockout creatures. Player motion can pass through enemy bodies; enemy body spacing is not a full mutual character-collision system. Small scenery and exterior buildings are not interiors. The guardian arena is open-air, not an instance. Basic click gating is not macro/bot detection. World enemy/resource state resets on load, as in the preceding prototype.

Older engines/builds must not overwrite upgraded saves: 0.1.3 does not understand northern positions, expedition fields or new items. Keep a pre-upgrade backup.

For failures, include the Godot version, first engine error and `test-results.log`. A screenshot or short clip is useful for movement, collision and lighting issues that pass simulation checks.
